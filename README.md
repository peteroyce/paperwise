# paperwise

A retrieval-augmented question-answering service for PDFs. Upload a document, ask a
question in natural language, and get an answer back together with the page numbers the
answer was drawn from.

![License](https://img.shields.io/badge/license-MIT-blue)
![Python](https://img.shields.io/badge/python-3.11-blue)

## Features

- PDF ingestion with per-page text extraction (pypdf), whitespace normalisation, and
  automatic skipping of pages that contain no extractable text.
- Word-based chunking with a configurable overlap, so a sentence that straddles a chunk
  boundary is still retrievable from both sides.
- Persistent vector store on ChromaDB, using a cosine-distance HNSW index.
- Page-level citations: the page number travels with each chunk as metadata, so the
  `sources` array is built from retrieval, not from anything the model says.
- Answers generated by Claude under a system prompt that forbids answering outside the
  supplied excerpts.
- Server-sent-events endpoint for token-by-token streaming.
- Multi-turn queries — prior turns are passed straight through as the Anthropic
  `messages` array.
- Upload hardening: extension check, 50 MB size cap, `%PDF` magic-byte check, and
  filename flattening before anything is written to disk.
- Re-ingesting the same `doc_id` replaces its chunks rather than duplicating them.

## Architecture

```
POST /documents/upload
        │
        ▼
  src/main.py ─── validate (extension, size, %PDF magic) ─── write to UPLOAD_DIR
        │
        ▼
  src/ingestion.py
        ├── extract_text()  pypdf → [(page_no, text)]
        ├── chunk_text()    CHUNK_SIZE words, stride CHUNK_SIZE − CHUNK_OVERLAP
        └── ingest_pdf()    → ChromaDB collection "paperwise" (hnsw:space=cosine)
                              metadata: {doc_id, page, filename}

POST /query
        │
        ▼
  src/ingestion.retrieve()  top-K nearest chunks, optionally scoped to one doc_id
        │                   score = 1 − cosine distance
        ▼
  src/llm.answer()          excerpts + question → Claude (system prompt: cite pages,
        │                   refuse if not in the excerpts)
        ▼
  {answer, sources[], model, usage}
```

| Module | Responsibility |
|---|---|
| `src/config.py` | Environment-backed settings (pydantic-settings); fails loudly if the API key is missing |
| `src/ingestion.py` | Extraction, chunking, ChromaDB read/write, document listing and deletion |
| `src/llm.py` | Context-block assembly, system prompt, blocking and streaming Claude calls |
| `src/main.py` | FastAPI routes, upload validation, SSE wrapper |

The API key is validated when `src.config` is imported, and the FastAPI lifespan handler
re-raises that failure at startup. The intent is that a misconfigured deployment fails
when it boots rather than on a user's first question.

## Quickstart

```bash
cp .env.example .env      # then set ANTHROPIC_API_KEY

python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt

uvicorn src.main:app --reload
```

Interactive docs at `http://localhost:8000/docs`.

Environment variables read by `src/config.py`:

| Variable | Default | Purpose |
|---|---|---|
| `ANTHROPIC_API_KEY` | — | Required. Startup fails if unset or blank |
| `CHAT_MODEL` | `claude-3-5-sonnet-20241022` | Model used for answer generation |
| `CHROMA_PERSIST_DIR` | `./chroma_store` | ChromaDB on-disk location |
| `UPLOAD_DIR` | `./uploads` | Where accepted PDFs are stored |
| `CHUNK_SIZE` | `512` | Chunk length in words |
| `CHUNK_OVERLAP` | `64` | Words shared between adjacent chunks |
| `TOP_K` | `5` | Chunks retrieved per query |

Embeddings come from ChromaDB's built-in default embedding function; no separate
embedding provider is configured.

## API

| Method | Path | Description |
|---|---|---|
| `POST` | `/documents/upload` | Multipart upload of a PDF; optional `doc_id` form field |
| `GET` | `/documents` | List ingested documents |
| `DELETE` | `/documents/{doc_id}` | Remove a document's chunks and its stored file |
| `POST` | `/query` | Ask a question; returns answer, sources, model, token usage |
| `POST` | `/query/stream` | Same input, streamed as `text/event-stream` |
| `GET` | `/health` | Liveness check |

```bash
curl -X POST http://localhost:8000/documents/upload -F "file=@research.pdf"

curl -X POST http://localhost:8000/query \
  -H "Content-Type: application/json" \
  -d '{"query": "What are the main findings?", "doc_id": "abc123"}'
```

Response shape:

```json
{
  "answer": "... (page 4)",
  "sources": [{ "filename": "research.pdf", "page": 4, "score": 0.91 }],
  "model": "claude-3-5-sonnet-20241022",
  "usage": { "input_tokens": 1240, "output_tokens": 180 }
}
```

Multi-turn requests add a `history` array of `{"role", "content"}` objects, which is
prepended to the messages sent to Claude.

The streaming endpoint emits `data: <text delta>` frames, terminated by `data: [DONE]`,
or `data: [ERROR]` if generation fails part-way. It carries text only — call `/query` if
you need the `sources` array.

## Tech stack

Python 3.11 · FastAPI · Uvicorn · ChromaDB · pypdf · Anthropic SDK · pydantic-settings · pytest

## Testing

```bash
pytest tests/ -v
```

`conftest.py` injects a dummy `ANTHROPIC_API_KEY` before any application module is
imported, and the tests mock ChromaDB and the Anthropic client, so no network access or
real key is needed. The same command runs in GitHub Actions on Python 3.11
(`.github/workflows/ci.yml`).
